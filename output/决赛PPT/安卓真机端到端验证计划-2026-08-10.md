## 2. 决赛包构建

### 2.1 预检

```powershell
node scripts/check-android-build-ready.mjs
npm run tsc:rn
npm test -- --runInBand
adb devices -l
```

手机设置：

1. 开启开发者选项和 USB 调试。
2. USB 模式选择“传输文件”。
3. 手机出现 RSA 授权框时选择“始终允许”。
4. `adb devices -l` 必须显示一行状态为 `device`，不能是 `offline` 或 `unauthorized`。

### 2.2 构建包含 BLE + MNN 的 debug APK

本机全局 Gradle 缓存曾出现 `file-access.bin` 损坏，因此本次使用仓库内独立缓存，并显式复用已有 JDK 17：

```powershell
cd android
$env:JAVA_HOME='C:\Users\PC\.gradle\jdks\eclipse_adoptium-17-amd64-windows.2'
$env:Path="$env:JAVA_HOME\bin;$env:Path"
$env:GRADLE_USER_HOME=(Resolve-Path '..').Path + '\.gradle-local'
.\gradlew.bat assembleDebug -PenableMnn=true -PmnnSourceRoot=D:/Projects/MNN --no-daemon
```

产物：

```text
android/app/build/outputs/apk/debug/app-debug.apk
output/Catune-决赛真机验证-2026-08-11-debug.apk
```

已构建产物：225,197,819 bytes，SHA-256：`CDEAF8F097777B63985DCED88CCFCC0CEFFEB9EB5BD5B3B69E031A54B6AD7C54`。

构建后检查 APK：

```powershell
Get-Item android/app/build/outputs/apk/debug/app-debug.apk
jar tf android/app/build/outputs/apk/debug/app-debug.apk | Select-String 'lib/arm64-v8a/libMNN.so|libposture_ai_bridge.so'
```

通过标准：APK 更新时间为本次构建；同时包含 `libMNN.so` 和 `libposture_ai_bridge.so`。

## 4. App 基础链路

按顺序验证并录屏：

1. 首启问卷完成后进入 Desk。
2. Desk → Plant → Monitor → Settings 来回切换。
3. Settings 切换中文/英文后，页面无截断。
4. Preview Sandbox 依次切换 NORMAL / SLUMPED / TECH_NECK / LEFT_LEAN / OFFLINE。
5. 检查猫姿态、角度、提醒文案、震动、跟练入口、植物积分和离线提示。

通过标准：五个状态均可触发；异常入态有一次震动；模型不可用时规则文案仍显示。

## 5. MNN 与 SME2 链路

### 5.1 先验证中文稳定性

1. Settings → 模型管理，确认活跃模型为 Qwen2.5-0.5B。
2. 检查五个模型文件完整：`config.json`、`llm_config.json`、`llm.mnn`、`llm.mnn.weight`、`tokenizer.txt`。
3. 使用固定 prompt：

```text
请用一句不超过30字、有温度的中文提醒我坐直，语气温和，不要医疗诊断。
```

4. 连续运行 3 次 INFER，记录输出、TTFT、Decode TPS、tokens 和 backend。

如果仍输出非中文，按此顺序排查：活跃模型目录 → tokenizer 文件 → instruct prompt 模板 → 模型/权重是否混用 → 清空模型后重新下载。不要先归因于 SME2。

### 5.2 再验证 SME2

```powershell
adb logcat -c
adb logcat | Select-String -Pattern 'sme2|CatuneMnn|MNN|posture_ai_bridge'
```

合法的“SME2 已加速”证据必须同时具备：

- App：`hw sme2=true`
- App：`lib sme2=true`
- App：`backend=SME2`
- logcat：MNN 能力探测出现 `sme2: 1`
- 同一模型、prompt、token 上限下有三轮 TPS 均值

任一项缺失时只说“APK 已编入 SME2 支持，当前运行时尚未选中”。

## 7. ESP32-S3 + BNO085 真实链路

### 7.1 接线与烧录

| BNO085 | ESP32-S3 |
| --- | --- |
| VIN | 3V3 |
| GND | GND |
| SDA | GPIO8 |
| SCL | GPIO9 |

Arduino IDE：

1. 板型选择 `ESP32S3 Dev Module`。
2. 安装 `Adafruit BNO08x`。
3. 烧录 `firmware/catune_node/catune_node.ino`。
4. 串口监视器设为 115200。

通过标准：串口依次出现 `0x4A <- BNO085`、`BNO085 OK`、`Catune-Node 广播中`。

### 7.2 App 连接

1. 手机开启蓝牙和附近设备权限。
2. Settings 选择硬件姿态带并开始扫描。
3. 状态变成 `connected` 后坐直并校准。
4. 前倾、后仰、左倾、右倾各保持 3 秒。
5. Monitor 观察角度；Desk 观察猫姿态和建议；恢复坐直确认状态回正。
6. 关闭 S3 电源，确认 App 显示断连并能回退手机 IMU/mock。

通过标准：三次冷启动均能在 30 秒内连接；动作到 UI 的反馈无明显迟滞；断连不 crash。

## 8. 决赛演示顺序与兜底

现场主链控制在 90 秒：

1. 展示 `Catune-Node connected`。
2. 坐直校准。
3. 前倾触发猫姿态变化、角度、震动与建议。
4. 打开 30 秒跟练。
5. 展示 MNN Benchmark 的中文输出与 SME2 证据截图。

兜底顺序：

1. BLE 失败：切 Preview Sandbox 固定场景。
2. MNN 失败：保留规则文案，播放预录 Benchmark 视频。
3. 网络失败：所有模型、截图和视频使用本地文件。
4. App crash：现场装第二台手机的冻结 APK，主机不临时改包。
